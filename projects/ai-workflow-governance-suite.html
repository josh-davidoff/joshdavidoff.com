AI enablement

AI workflow governance suite

Hooks, a skill, and four scheduled tasks that capture every AI-assisted coding session, brief me on it by morning, and hand every proposed change back to a person to rule on.

The problem

Eight months of building with coding agents across roughly twenty projects had produced no durable record of any of it. The only history lived in the agents' session caches, which are designed to be pruned, and the most useful signal from each session, the tool calls I rejected, the corrections I typed, the tests that failed, evaporated when the session ended.

The obvious fix was to let an agent maintain its own instructions and memory. I did not want that. An agent that edits its own operating rules unattended is the automation-bias failure I argue against in The Bot Stops Here. The constraint was to automate collection and synthesis completely while keeping every write-back behind a human decision.

What it does

Collect, automatically

  • A session-start hook re-mines the Codex and Claude Code caches into a metadata-only timeline: dates, working directory, models, tool counts. No conversation content, which would drag employer and financial material into the record.
  • A session-end hook writes one stub per session: where it happened and what the repository looked like afterward.
  • A nightly digest builder walks every transcript and repository touched since the last run and keeps, in priority order, every prompt I typed, every rejected tool call and correction, every error and failed test, and what changed.

Synthesize, automatically

  • At 2:25am a scheduled task reads the digest and writes one brief: what broke, what to build, how the agent setup should improve, and what memory changed.
  • Suggestions carry night to night in a threads file, and a backlog holds every idea until I rule on it. Anything unruled for seven nights is flagged.
  • The nightly task hands items to the sweep that owns them: a Monday register sweep for tests, tier drift, and model pins; a twice-monthly review of the instruction files; a twice-monthly security sweep. Each reports and offers.

Assimilate, deliberately

  • Nothing in the suite edits code, configuration, instructions, skills, or memory unattended. Every proposed change is a one-line suggestion I carry into a live session.
  • A /log skill turns what I describe into a project dossier, a build-log note, or a tools-ledger note, private by default.
  • The register renders this site from the entries flagged public, using only the card fields. A project can appear on the homepage while its write-up stays private.

Architecture

Hooks and a nightly digest collect → a 2:25am brief synthesizes and hands off to the sweeps → every proposal reaches a person → the person acts in a live session and logs the outcome, which the next night's digest reads.

Hardening that mattered

The register also audits the agents' dependencies. A model ID hardcoded in a deployed service fails unattended, so a checker inventories every pinned model across the workspace and ranks it by blast radius against the deployment inventory. It does not decide what is obsolete, since there is no offline way to know a current lineup and a confident wrong answer is worse than a list. It reports three states instead: checked against my reference file, observed working in one of my own sessions on a given date, or unverified.

Only the region between two markers in that reference file counts as verified. Otherwise writing "this model is not yet verified" would mark it verified. The weekly sweep runs the workspace's nineteen registered test suites and flags any project whose blast radius has outgrown its tests.

How I built it with AI

The history came from 162 rollout files in a rolling cache, and three modeling problems inflated the numbers until each was handled: resumed threads get a fresh file under the original id, subagents write sidecar transcripts under the parent session, and a session's working directory changes as it runs. 162 files were 140 threads. The archive now holds 265 sessions back to February 2026, across 34 project dossiers and 24 tools-ledger entries.

Before the renderer could generate anything, it had to reproduce the eleven hand-written homepage cards byte for byte. The safeguards were built to fail differently: the generated ignore file used a trailing comment on a token pattern, which gitignore does not support, so the pattern matched nothing while looking correct. An independent filename scan caught the OAuth files anyway.

When I ran a review of every active project through parallel reviewer agents, four claims that two helpers were byte-identical were wrong, one zero-coverage claim pointed at a path that already had a test, and one unused-dependency claim was half wrong. Agents propose. Verification is a separate step.
