AI uplift

AI workflow governance suite

Scheduled tasks record every AI coding session and brief me each morning. Nothing they propose takes effect until I approve it.

The problem

After eight months of building with coding agents across about twenty projects, I had no lasting record of any of it. The only history sat in the agents' session caches, which clear themselves out. The most useful moments, when I rejected a step or corrected the agent or a test failed, disappeared when each session ended.

The obvious fix was to let an agent maintain its own instructions and memory. I did not want that. An agent that edits its own operating rules unattended is the automation-bias failure I argue against in The Bot Stops Here. So the system collects and summarizes everything on its own, and nothing it proposes takes effect until I approve it.

What it does

Collecting

  • When a session starts, a hook logs when and where it ran and which model it used. It saves nothing from the conversation, which keeps work and financial details out of the record.
  • When a session ends, a second hook notes where it happened and what the code looked like afterward.
  • Each night a script reads every session and project touched since the last run. It keeps what I typed, every place I overruled the agent or a test failed, and what changed.

Summarizing

  • At 2:25 a.m. a scheduled task turns that digest into a brief on what broke, what to build next, and how the setup could improve.
  • Open suggestions carry over from night to night until I decide on them, and anything left for a week gets flagged.
  • Bigger items go to scheduled reviews. A Monday sweep checks tests and model versions, and twice a month separate reviews cover the agents' instructions and security. Each one reports and proposes but changes nothing.

Deciding

  • Nothing in the suite changes code or the agents' instructions on its own. Every proposal reaches me as a one-line suggestion, and I make the change myself in a live session.
  • A /log command turns my description of what I built into a project note, private unless I mark it public.
  • The project cards on this site's homepage are generated from the notes marked public, so a project can appear here while its full write-up stays private.

Hooks and a nightly digest collect → a 2:25am brief synthesizes and hands off to the sweeps → every proposal reaches me → I act in a live session and log the outcome, which the next night's digest reads.

Safeguards

The register also tracks which AI model versions my deployed tools depend on, since a retired model breaks a scheduled job with no one watching. It doesn't guess which models are current. It marks each one as checked against my reference list, seen working on a given date, or unverified. A weekly sweep also runs the workspace's nineteen test suites and flags any project that has outgrown its tests.

How I built it with AI

The history came from 162 files in a rolling cache. Three quirks inflated the count until I handled each one. A resumed session starts a new file under its old ID, helper agents write their own transcripts, and a session can switch folders partway through. The 162 files turned out to be 140 sessions. The archive now holds 265 sessions going back to February 2026.

Before the generator could write any homepage cards, it had to reproduce the eleven existing cards exactly. I also built two separate checks to keep private files from being published. One had a syntax error that made it match nothing while looking correct, and the other still caught the private files.

When I had reviewer agents audit every active project, six of their claims were wrong or half wrong, including four that called two pieces of code identical. I check every agent finding before acting on it.
